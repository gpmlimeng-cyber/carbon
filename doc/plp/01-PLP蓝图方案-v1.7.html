01执行摘要

立项报告的四个问题（无计划底座、移交无固化、过程无留痕、系统孤岛）都成立；但全量范围在 7 个月内不可达。 本蓝图给出的解法是：把“项目主干”做厚，把“板块前端”做薄，把“专业记录”留给专业系统。

三条必须写进方案的边界

① 项目主数据归 PLP

项目号、阶段、计划、里程碑、交接与卡点由 PLP 拥有；订单、库存、成本、财务归 SAP，用项目号 + charge number 关联。

② 不重算 MRP、不做库存账

物料计划由 SAP 输出，PLP 只承接“需求行 → 供应承诺 → 进度跟踪 → 卡点校验”，不产生第二套库存与成本。

③ 审批优先复用 OA

PLP 只做业务节点校验与留痕，不重建审批中心；既降低许可依赖，也回应“审批链路冗长”的诉求。

四个结论

  • 范围要分两批：2027-06 前交付“主干 + 供应链 + 工程交接 + 售后”，移动离线、驾驶舱、Agent 放下半年。
  • 里程碑二要收缩：从“全链路流程上线”改为“主数据 + 计划/里程碑 + 看板 v0”，否则会连锁拖累 M3–M4。
  • 交接与卡点是一号工程：直接对应“结构性短板”，也是业务最快感知价值的地方。
  • 先做 4 周 PoC：主干 + PDM/SAP 两条接口，通过再签外部开发合同。

2.2 明确不做（防止范围蔓延）

不做原因与替代
财务总账、成本核算、库存账SAP/财务系统为唯一账本；PLP 只读汇总并做项目维度展示
MRP 运算与排产求解SAP/MES 输出计划结果；PLP 跟踪承诺与进度
招投标评标全流程（一期）模型复杂、低频；一期只做招标台账与合同挂接
离线填报（一期）技术独立、风险高；一期先上在线移动审批/拍照/上报，离线单独立项
重建审批中心复用 OA，PLP 只做节点校验与留痕

2.3 建设原则（承接立项报告）

  • 总体规划、分步实施：先定主数据与接口标准，再按板块交付。
  • 业务主导、统一承建：板块是需求与验收主体，数字化部统一技术标准。
  • 一数一源、全程共享：字段级 owner，谁产生谁维护。
  • 节点卡卡、过程留痕：卡点可阻断、留痕可回放。

03业务方案

系统是载体，业务才是内容。本章回答四个问题：业务上要变成什么样、谁在什么节点负责什么、 哪些事必须按规则办、以及怎么衡量它真的变好了。

3.1 业务目标与价值主张

业务目标一句话：让每一个大储项目从签约到转运维，都在一条线上跑，且每个责任交接都有凭证、每个关键节点都有闸门。

可控

管理层打开一个项目，能看到走到哪一步、谁在做、下一步卡在谁那里、还差什么。周进度不再靠人汇总。

可交

板块之间换手有交接单：交什么、谁交、谁接、什么时候接、双方签了没有。出了问题能定位到人。

可复用

计划模板、问题库、复盘结论沉淀在平台里，新人接手同类项目不必从零摸索。

3.3 目标业务模式：一条主线、四个交接、八个卡点

业务上只改三件事：计划统一（一套模板、一套里程碑）、交接留证（四个换手点双签）、 卡点前置（八个闸门，未过不推进）。其余流程尽量保持业务现有习惯，避免“为了系统改业务”。

要素业务含义落地要求
一条主线立项投决 → 商务手续 → 招采供货 → 工程交付 → 售后运维五阶段状态由业务动作驱动，不允许手工跳步
四个交接H1 计划→营销、H2 营销→供应链、H3 供应链→工程、H4 工程→运维交接单双签，资料清单必传，未签阶段不推进
八个卡点G1 无立项不建档 … G8 质保未绑定不移交能自动判的自动挡，需人担责的走特批（见第 9 章）

3.8 变革与推广路径

  • 试点（2 个项目，3 个月）：1 个国内大储 + 1 个海外，只跑“主干 + 交接 + 4 条卡点”，验证再推广。
  • 分层培训：管理层看驾驶舱与预警；项目经理学计划与交接；业务岗学本板块表单与卡点。
  • 考核挂钩：立项报告已有专项激励，建议把“交接线上完成率、资料归档率”纳入部门月度考核。
  • 月度复盘：卡点阻断/豁免 Top10、交接驳回原因 Top5，直接进下月流程优化清单。

04总体架构：业务架构 + 平台视图

先讲业务怎么运转，再讲系统怎么支撑。业务核心架构是一张“经纬网”：横向是项目走过的价值流阶段，纵向是计划、物料、资金、责任四条贯穿始终的管理线。 每一个交叉格子里，都同时存在一个业务对象、一个责任主体和一个可被校验的节点。

4.1 业务核心架构：一条价值流 × 四条管理线

图 4-1 是本方案的“母图”：横轴是 ① 价值流层，纵轴是 ② 管理线层，交叉格子由 ③ 执行层（五大板块）负责， 格子里的闸门与交接点属于 ④ 管控层，贯穿全表的项目号与字段属于 ⑤ 数据与集成层。 4.8 的五层结构，就是这张图的展开。

4.2 阶段一 · 立项投决

阶段目标：回答“做不做、按什么目标做、用多少钱做”，把商机变成一份可执行的项目基线与预算。

输入：客户需求/商机、技术方案初稿、投资估算、交付能力评估　→　输出：投决批复、项目编号、总体计划基线、预算与回款预测

管理线本阶段要做的事关键动作/对象产出与判据
计划线套用项目类型模板，形成总体计划与里程碑基线里程碑定义、关键路径、资源与产能初排计划基线发布；里程碑可被后续阶段引用
物料线识别长交期与瓶颈物料，判断供应可行性电芯/PCS/主变等长交期清单、备选供应方案长交期清单与首单建议时间
资金线投资估算与资金计划，明确毛利目标与回款节奏投资测算、付款计划草案、回款预测预算获批；项目级资金计划建档
责任线明确投决责任与项目经理任命投决会签字、项目 owner、目标责任书G1 通过：有批复才允许建档

关键流程：① 商机登记 → ② 技术方案与可行性 → ③ 投资测算与产能评估 → ④ 投决会审议 → ⑤ 项目建档与编号 → ⑥ 计划基线与预算发布。

交接与卡点：H1 立项投决 → 商务手续；G1 无立项不建档（无投决批复不允许创建项目）。

4.3 阶段二 · 商务手续

阶段目标：把“合同怎么签、手续怎么办”落成可排产、可下单的前置条件，避免无手续排产。

输入：投决批复、技术方案、客户商务条件　→　输出：销售合同、技术协议、八大局要件台账、排产许可

管理线本阶段要做的事关键动作/对象产出与判据
计划线编制手续节点计划，与排产/发运里程碑倒排要件节点、责任人与办理时限手续计划与总计划对齐，逾期可预警
物料线冻结 BOM 与技术协议，锁定选型与长交期技术协议评审、BOM 冻结、变更走变更单协议签署；BOM 版本锁定
资金线落实合同付款条件与预付款付款条款、保函、预付款到账预付款到账或授信落实
责任线要件 owner 到人，合规签字留痕并网/土地/规划/施工/开工许可G2 通过：要件齐或带期限豁免

关键流程：① 合同评审 → ② 签约与预付款 → ③ 技术协议确认 → ④ 八大局要件办理 → ⑤ 要件核验 → ⑥ 发出排产许可。

交接与卡点：H2 商务手续 → 招采供货；G2 手续未办结不排产、G3 无技术协议不下单（例外走 L3 特批，带期限）。

4.4 阶段三 · 招采供货

阶段目标：把“什么时候、什么货、到哪”变成可承诺、可跟踪、可校验的供应。

输入：已冻结 BOM、排产许可　→　输出：采购订单、生产订单、发运计划、到场签收单

管理线本阶段要做的事关键动作/对象产出与判据
计划线开工会定排产与交付里程碑，形成周计划开工会纪要、排产里程碑、发运节点排产计划与项目里程碑一致
物料线需求分流（库存/外购/自制），跟踪备料—到货—生产—发运四节点需求行、供应承诺、齐套率、承诺偏差G4 齐套率 ≥95%；G5 偏差 >3 天升级
资金线按合同与到货节点付款，管理资金占用采购付款、到货款、发票付款与到货/验收节点匹配
责任线供应链对承诺日期负责，供应商履约评价齐套责任人、供应商交付评价承诺达成率可统计

4.8 五层业务结构

一条主轴、三层业务、一层规则、一个底座。这里的“层”不是按“数据/界面”切，而是按“回答哪个问题”切： 每层只回答一个问题，也只被上一层的动作触发、被下一层的规则约束。

四条层间规则

  • 依赖单向：执行层的推进只能经管控层校验，不能绕行；数据与集成层只被读，不被业务写入。
  • 一层一 owner：价值流层 PMO；管理线层 经营计划；执行层 五大板块负责人；管控层 PMO + 审计；数据层 数字化部。
  • 一层一指标：每层只报一个主指标（见表 4-2 末列），避免指标泛滥。
  • 不越级：跨层只看两条路——业务动作（执行→价值流）、规则校验（执行→管控），其余均只读。

4.9 总体架构（平台视图）

业务架构回答“怎么运转”，平台视图回答“由什么承载”。两者是上下对应关系：PLP 承上（项目主干与执行）， 专业系统承下（订单、库存、成本、BOM、制造），数据层横向支撑看板与分析。跨层只走网关。

4.11 架构原则

  • 业务主线优先：系统结构跟着价值流和四条管理线走，不为技术方便改业务。
  • 一数一源：项目主数据在 PLP，订单/库存/成本在专业系统，字段级 owner 制。
  • 专业系统各司其职：PLP 不重算 MRP、不做库存账、不建财务总账。
  • 卡点前置、责任可追：关键节点设闸门，交接双签，过程留痕可回放。
  • 分层不越级：执行层的动作必须经管控层校验，不允许直连数据层改事实。
  • 可演进：一期只做主干与四个交接点，规则可配置但不过度设计。

05应用架构：五阶段工作台 × 四条主线中枢

应用不按部门切，而按两条轴切：横轴是阶段——谁在什么时候干活，对应五个工作台；纵轴是主线——同一件事跨阶段怎么管住，对应四个中枢。 工作台是入口，中枢是能力；中枢没有独立菜单，以页签和服务的形式出现在每个工作台里。

5.1 规划方法：两轴切分，一条底座

切法得到什么好处要避免的错法
按阶段切5 个工作台：立项投决、商务手续、招采供货、工程交付、售后运维用户在“我现在干的这一段”里就能完成全部动作按部门切 → 系统复制组织结构，跨部门还是要来回跳

10.1 部署与容量

  • 环境：开发 / 测试 / 生产三套；测试用脱敏数据，禁止直连生产。
  • 生产：私有云，应用双副本无状态；PostgreSQL 主备 + WAL 归档；对象存储多副本。
  • 备份：全备日备 + 连续归档；RPO ≤ 15 分钟、RTO ≤ 4 小时；季度演练恢复。
  • 发布：按季度版本，迁移前自动备份、失败可回滚；重大变更走评审。

12.3 变更管理

  1. 提出：板块或项目经理提交变更申请，写清原因、影响范围（范围/工期/成本/接口）。
  2. 评估：PMO 在 3 个工作日内出影响评估，涉及范围或预算的同步财务。
  3. 分级审批：一般变更（不影响里程碑）由 PMO 批；重大变更（影响里程碑/预算/跨板块）报数字化委员会。
  4. 实施与回写：变更单关联到项目基线，实施后更新基线并留痕；未关联变更单的计划调整一律视为违规。
