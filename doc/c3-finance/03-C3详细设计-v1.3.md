# 第一部分 需求

## 1. 范围与三个对象

| 对象 | 时间口径 | 核心问题 |
| --- | --- | --- |
| 收入 | 权责发生，按 **WBS 进度** | 该确认多少、什么时候确认 |
| 发票 | 开票日（纳税义务） | 该开多少、开了多少、红冲多少 |
| 回款 | 到账日 | 收了多少、核销给谁、还差多少 |

**原则**：三者解耦、可对账；差异必须有原因、可下钻。

### 1.1 销售订单与项目的关系（新增）

| 关系 | 场景 | 处理 |
| --- | --- | --- |
| **N:1（默认）** | 一个项目多张订单：设备、安装服务、备件、补充协议 | 一个项目挂多张订单，标一张主订单 |
| 1:1 | 标准 EPC，一合同一项目 | N:1 的特例 |
| 1:N | 框架合同分多期/多站 | 订单行按项目拆分 |
| 1:0 | 先投决立项、后签单 | 允许项目先存在 |

- **账务主体是订单**（法定收款依据），**管理维度是项目**（考核与现金流）；
- 关联表 `sales_order_ref`，唯一键 `(orderNo, itemNo)`；
- **Carbon 的 `salesOrder` 无 project 字段**（实测 0 列），必须新建关联表，不改核心表。

### 1.2 款项归属结论

| 对象 | 主键 | 说明 |
| --- | --- | --- |
| 收款条件 | 订单 | 条款在合同/订单 |
| 预收款 | 订单 | 先款后票，开票后冲抵 |
| 发票 | 订单行 + 项目（双键） | 订单号给 SAP 对账，项目号给管理归集 |
| 应收 | 继承发票 | 派生视图 |
| 回款 | 客户 + 核销到发票 | 核销后自动获得双维度 |

## 2. 角色与三个入口

| 入口 | 给谁 | 内容 |
| --- | --- | --- |
| **项目 → 资金**（主） | 项目经理、板块负责人 | 父页：资金总览 + 三账对账；子菜单：收入 / 开票 / 回款 |
| **订单 → 收款进度**（次） | 商务、财务对账 | 该订单开票/回款/余额 |
| **应收工作台**（岗位） | 财务应收 | 跨项目：待开票、待核销、逾期、关账 |

## 3. 指标

收入确认及时率 ≥95%、开票及时率 ≥90%、回款率 ≥90%、逾期识别 100%、DSO 同比 −15%、三账差异说明率 100%。

# 第二部分 功能设计

## 4. 设计总览

### 4.1 对象 → 表 → 页面

| 域 | 对象 | 表 | 页面 |
| --- | --- | --- | --- |
| 订单关系 | 订单引用 | `sales_order_ref`、`element_allocation` | 项目/订单区块 |
| 收入 | 计划、确认、快照 | `revenue_plan`、`revenue_entry`、`revenue_snapshot` | 收入台账、收入计划 |
| 发票 | 申请、发票、红冲 | `invoice_request`、`invoice` | 开票管理 |
| 收款条件 | 条款 + 触发器 | `receipt_term` | 合同/订单配置 |
| 回款 | 回款、核销、预收 | `receipt`、`allocation`、`advance_receipt` | 回款与核销 |
| 对账 | 三账 | 视图 | 三账对账 |

### 4.2 页面结构与路由

```
/x/project/:id/finance            ← 资金总览 + 三账对账（父页，两个区块）
/x/project/:id/finance/revenue    ← 收入
/x/project/:id/finance/invoices   ← 开票
/x/project/:id/finance/receipts   ← 回款
```

导航结构（与「成本」一致：父项 + 缩进子项，扁平数组 + `indent: true`）：

```
概览
计划
排程
成本
  库存          ← indent
  配对          ← indent
  账单          ← indent
资金            ← 父页：总览 + 对账
  收入          ← indent
  开票          ← indent
  回款          ← indent
时间
```

**分法原则**：综合性的、跨子项的放父页（总览、对账）；单一对象的明细操作放子菜单（收入、开票、回款）。这样父页回答“整体怎么样、三账平不平”，子项回答“这笔怎么处理”。

- 复用 `useProjectNavigation` 的 `ProjectSidebarLink` 类型（`indent?: boolean`），**不引入折叠组**；
- 子项默认全显，空态给引导（避免像「库存/配对」那样被误以为功能不存在）；
- 「质保金」这类可选子项在 P4 用条件显示（有 warranty 才出现）；
- 左侧元素树为**过滤器**（见 5.2），选中节点写入 `?element=`。

### 5.4 三个核心屏

**收入台账**：期间/计划/确认/差异/口径/状态；行内确认、红冲；差异负值标黄需说明。

**回款核销**：建议列表（等额优先、到期日 FIFO）+ 勾选 + 余额校验；必须人工确认才落库；预收款显示「预收余额可冲抵」。

**三账对账**（在父页）：收入−开票、开票−回款、合同资产；差异①必须选原因才能关账。

## 7. 状态机

### 7.1 收款条件 `receipt_term`

```
Draft ─启用─> Active ─触发─> Triggered ─开票─> Invoiced
                  │              └─撤销（节点回退）─> Active
                  └─失效（节点被删/拆）─> Invalid（需重绑）
```

### 7.2 收入 / 发票 / 回款

沿用 v1.0：收入 Draft→Submitted→Approved→Posted→Reversed；发票 Draft→Issued→PartiallyPaid→Paid→Voided；回款 Draft→Confirmed→Allocated→Closed。

## 8. 关键算法

### 8.1 收入：WBS 加权完工百分比

```
P = Σ(weight_i × progress_i) / Σ(weight_i)     // weight = 预算成本占比
封顶：若关键节点（并网/验收）未通过，其父节点 progress ≤ 90%
累计应确认 = 合同额（含已批变更）× P
本期确认 = 累计应确认 − 已确认
若本期确认 < 0 → 需审批（收入回退）
每次确认写 revenue_snapshot（P、合同额版本、各节点进度）
```

**口径**：
- 权重默认取预算成本，可手工调整（需理由）；
- **设备到场不计进度**，单列「待安装」，避免收入提前；
- 进度来源：任务/节点状态汇总 + 项目经理月度确认，财务复核。

### 8.2 防虚报三闸

| 闸 | 规则 |
| --- | --- |
| 里程碑封顶 | 关键节点未过，父节点 ≤ 90% |
| 交叉校验 | 进度 vs 实际成本、设备到场、验收偏差 >10% 触发复核 |
| 月度锁账 | 确认→审批→锁定；修改需反关账 |

### 8.3 应收：按收款条件节点，不按进度

```
某节点应收 = 合同额（含变更）× 节点比例
累计应收 ≤ 合同额；尾差由最后节点吸收
合同资产 = 累计已确认收入 − 累计已开票（≥0）
```

- 应收以**开票**或**无条件收款权**（节点达成 + 合同约定）为准；
- 未开票先到节点 → 合同资产（或应收未开票），开票后转正式应收；
- **收入与应收的差 = 合同资产**，三账里单列一行。

### 8.4 收款条件触发

```
on element.completed(elementId, stateId):
  terms = receipt_term where triggerType='WBS' and triggerRef=elementId
          and status='Active'
  for term in terms:
      if exists(trigger_event(term.id, event.id)): skip   // 幂等
      create invoice_candidate(term, event)               // 待办，不生成应收
      mark term Triggered
```

| 规则 | 行为 |
| --- | --- |
| 幂等 | `(termId, eventId)` 唯一 |
| 补触发 | 条件晚于节点完成配置 → 扫描历史事件补生成 |
| 回退 | 节点进度回退 → 撤销未处理待办；已开票不回滚（走红冲） |
| 失效 | 节点删除/拆分 → `Invalid`，提醒重绑，不静默丢 |

### 8.5 预收款冲抵

```
advance_receipt(status=Open) → 开票时选择冲抵
allocation(receiptId=null, advanceReceiptId=...)  // 二选一
冲抵后 advance 余额减少；不足部分走正常回款
```

### 8.6 账龄 / 核销 / 逾期

沿用 v1.0：账龄按到期日自然日分桶、月末快照；核销建议等额优先 + FIFO，人工确认；逾期 T+1/7/30/90 升级，幂等键 `(invoiceId, level)`。

## 14. 异常与边界

| 场景 | 处理 |
| --- | --- |
| 节点完成但无收款条件 | 记事件，不生成待办；配置后补触发 |
| 节点回退 | 撤销未处理待办；已开票走红冲 |
| 一票多节点 | `element_allocation` 分摊，比例合计 100% |

| 合同变更 | 收入按新版合同额重算，差额当期调整 |
