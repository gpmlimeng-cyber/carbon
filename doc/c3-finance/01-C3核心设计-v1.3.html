01三个对象，一条对账线

资金中枢不是“财务系统”，而是项目维度的一条“权责—纳税—现金”链。三个对象各自成立，又必须能互相对上。

02三条设计原则

① 解耦但对账

收入、发票、回款是三个独立对象与台账，不做“开票即收入”；差异用对账视图管理，不靠人工台账抹平。

② 应收不落库

应收 = 发票 − 已核销，用视图计算，避免“发票改了应收没改”的双写问题；账龄按月快照防漂移。

③ 自动匹配只做建议

核销是资金动作，错了要人担责：系统给建议（等额优先、到期日 FIFO），人工确认才落库。

为什么不让系统自动核销

核销决定了“哪笔应收被清偿”，错了就是财务责任。系统只做候选排序与金额校验，落库前必须有人确认；差异 > 0.01 强制填原因。

06关键算法

6.1 收入确认

remaining = 合同额 + 已批变更 - 累计已确认
if 口径 == 节点:
    cap = min(节点计划额, remaining)
    校验 0 < 本次确认 <= cap
else:  // 完工百分比
    target = 合同额 × 进度%
    amount = target - 累计已确认        // 可能为负
    if amount < 0: 必须审批（收入回退）
累计已确认 += amount

6.2 账龄（自然日）

days = 今天 - 发票.到期日
bucket = days <= 0 ? 未到期
       : days <= 30 ? 1-30
       : days <= 60 ? 31-60
       : days <= 90 ? 61-90 : 90+
每月末快照一次，历史账龄不随日期漂移

6.3 自动核销建议

候选 = 同客户 且 未结清 的发票
if 回款附言含发票号: 精确匹配
else: 按 |金额-余额| 升序、到期日升序 → 等额优先，否则 FIFO 部分核销
输出建议 → 人工确认 → 落库（锁行 + 余额二次校验）

6.4 逾期升级

L1 到期+1  → 项目经理 / 财务应收：标记逾期
L2 +7      → 板块负责人：待办催收
L3 +30     → 财务负责人 + 管理层：要求回款计划
L4 +90     → 进入催收台账
幂等键 (invoiceId, level)，每日批跑，不重复通知
